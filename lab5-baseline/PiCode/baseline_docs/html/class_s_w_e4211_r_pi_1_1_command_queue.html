CommandQueueEntry CommandQueue::dequeue ( )

This method will dequeue the next command from the queue. This method will block if there are no items on the queue.

Returns
The return will be the next command that is to be processed.

This method removes and returns the next command from the front of the queue. If the queue is empty, the calling thread blocks until another thread enqueues a command.

Returns
The next command that is to be processed.

  1. Create a local CommandQueueEntry to hold the value that will be returned, and initialize all of its fields to zero.

  2. Block on the counting semaphore. If no items are on the queue, this blocks the calling thread until an item is enqueued.

  3. Lock the mutex so that no other thread can modify the queue while this thread is accessing it.

  4. Copy the item at the front of the queue into the return value, and then remove that item from the queue.

  5. Return the copied item.

◆ hasItem()

bool CommandQueue::hasItem ( )

This method will indicate whether or not the queue has an item that is ready to be dequeued.

Returns
true if there is an item on the queue. False otherwise.

This method indicates whether the queue currently contains at least one item that is ready to be dequeued. It does not block and does not remove anything from the queue. The result is only a snapshot: another thread may change the queue immediately afterwards.

Returns
true if there is at least one item on the queue. False otherwise.
  1. Lock the mutex before examining the queue. Even reading the queue is unsafe while another thread may be modifying it. As in the other methods, use a scoped lock.
  2. Determine whether the queue contains one or more items and return the result. Use the queue's own state to make this determination, not the value of the semaphore.
